to add an event listener to an element,

type is the event to listen for

capture is not required for it. default is false.
	true - The handler is executed in the capturing phase.
	false - The handler is executed in the bubbling phase.

		Capturing Phase: In this phase, the event starts at the root of the Document Object Model (DOM) tree (e.g., the window or document object) and propagates downwards towards the target element where the event originated. Event listeners set to capture during this phase will be triggered as the event "trickles down" the hierarchy. This phase is less commonly used for event handling but can be useful for global event interception or specific scenarios requiring early event handling.
		Target Phase: This is the phase where the event reaches the actual element that triggered it. Any event listeners directly attached to this target element will be executed during this phase.
		Bubbling Phase: After reaching the target element, the event then "bubbles up" from the target element back towards the root of the DOM tree. This is the default behavior for most JavaScript events. Event listeners set to bubble during this phase will be triggered as the event propagates upwards through the element's ancestors (parent, grandparent, etc.). This phase is frequently used for event handling, especially in conjunction with event delegation, where a single listener on a parent element can handle events from multiple child elements.

you know the basic logging in/out functions.

when you save passwords to databases plainly, once the db is accessed all the passwords are there to see.
to battle this flaw, we use encryption and hashing

one basic and weak encryption is ceaser cyphers. 
	gravity falls used this. just shift letters by a certain number called the key.
	so if the key is 4, ABC turns to EFG

another more secure one is aes256 encryption
while this isnt as sinple as shifting letters, this also uses a key to encrypt and once that key is found, the whole thinng crumbles

this whole key thing is really a big flaw.

--HASHING--

to remove this flaw, we hash instead

hashes are mathematical functions defined to make it almost impossible to go backwards once encrypted
	its like how its difficult to find the other 2 factors of 377 (apart from 1 and 377) but if you were given a question to multiply those 2 factors instead, youll get 377 easily
		the numbers are 13 and 29

--HACKING--

this is how hackers get passwords
	1. they can look at the database and find out the hashes
		- from this point, you can copy and paste the hash in google and search to see if it was previously cracked

	2. then they take things like the most common passwords used and make hashes for all of them, forming a hash table
			- the first place to get common passwords is the internet. (just search for 'most common passwords' on the internet)
		or
			- they also hash every word in the dictionary (about 150,000) 																		//this is a dictionary attack
			- they then hash all the numbers from a telephone book (about 5,000,000)
			- and then theyhash all combos of characters up to 6 digits (about 19,770,609,664)
			- they then add all of the hashes up.
				dont be fooled by the large number. modern gpus can calculate about 20,000,000,000 MD5 hashes per second
					this is different for bcrypt hashes (only like 17,000 per second)
				so all the stated above is less than a second of work
		or
			- just use one of the previously created hash tables out there on the internet

	3. then compare the db password values and the hash table values

to be more secure and safe against this attack, use long passwords

--SALTING--

now, a way to prevent dictionary attacks, or hash tables is to salt the password
this is addition of random characters in the password before hashing so the whole thing is hashed together

now, in bcrypt there's something called salt rounds. (how many rounds of salting is done)

a salt round is adding the salt to the password and hashing it.
	the second salt round is adding a salt to that hash from the first round and hashing it again. and so on

OAuth means Open authorization
it is an open standard for token based authorization
essentially, it enables the page access pieces of information from 3rd party sites 
for the purpose of this section, we're delegating the login security to google.
	for them to login to our own services, they can login on google and then google authenticates them using their own secure methods.
	google then sends a response to our site to either authenticate them or not

OAuth is special because it allows:
	Granular access level. 
		allows access to very specific things

	Read only or Read and Write Access

	Revoke access
		the user can revoce the access given to your website at any time
	
How does OAuth work
	1. Set Up Your App
		So the first step is to actually tell this third party about our web application because they don't know about us.
		we have to set up our app in their developer console, and in return we get what's called an app ID or a client ID, 
		and our website is then the client, which will make the request to authenticate our user.

	2. Redirect to Authenticate
		So when the user hits up your site and they want to authenticate, we give them an option to log in with the 3rd party site
		So once they click on that option, then we'll take them to the actual website so that they are seeing a familiar, trustworthy interface
		without OAuth, what we would have to do is to ask the user, for their login credentials for this other site. this is ledd trustworthy

	3. User Grants Permission
		once the user logs in on this third party, then they have to review the permissions that our website is asking for.
	
	4. Recieve authorization code
		the 3rd party site sends the authorization code tellin our site that the person logged in successfully so we should authenticate them
	
	5. Exchange AuthCode for Access Token (Optional)
		if we wanted to go a step further, we can also exchange our authentication code for an Access Token.
		And when we receive that Access Token from the site, we would save it into our database
		this is the token that we can use if we want to request for pieces of information, subsequently. 
		This access token is valid for a lot longer than the authentication token.
	
		So the Auth Code is what we need to authenticate the user that they successfully managed the login through
		The 3rd party and the access token is what we'll use to access pieces of information that are stored on that user's account on this third party's website, 
		for example, their email or their friends list (from facebook) etc.

what is web3?
Web3 is the 3rd iteration or stage of the internet

Web3, also known as Web 3.0, is a vision for the next generation of the internet. 
It's characterized by decentralization, user empowerment, and a move away from the centralized control of data and services prevalent in Web 2.0. 
Web3 leverages technologies like blockchain, cryptocurrencies, and decentralized autonomous organizations (DAOs) to create a more open, transparent, and user-owned internet. 
Here's a breakdown of key concepts:
	Decentralization:
		Instead of relying on a few large companies to control the internet's infrastructure and data, Web3 distributes control across a network of users and computers. 
	User Ownership:
		Users have more control over their data and online identities. They can participate in the governance and value creation of platforms they use. 
	Blockchain Technology:
		Blockchain, a distributed ledger, underpins many Web3 applications, providing transparency, security, and trust. 
	Token-Based Economies:
		Cryptocurrencies and tokens are used to incentivize participation, facilitate transactions, and represent ownership in Web3 systems.

what is the blockchain
it is essentially a Distributed Trustless ledger that uses hashing to prevent illegal changes to the data
	Distributed means many people have copies
	Trustless means we dont have to trust that noone changes anything because the other people will have proof if it happens

BLOCK
	it takes the data and hashes it.
	but to be identified as part of the blockchain, it needs to have a sort of fingerprint (let's say this fingerprint is that the hash starts with a certain number of zeros)
	to achieve this, something called a nonce (number used once) is added to the data before hashing. the nonce cycles from 1 onward till it finds a number that will make the hash contain the fingerprint
	the process of finding the right nonce is called mining
	changing the data changes the required nonce
	this process creates the BLOCK

CHAIN
	This is the collection of blocks
	each block in a chain takes the hash of the previous block into account
	the first (genesis) block has no previous block so the hash it takes into account is just 16 seroz (hashes have 16 digits)
	the data is combined with the previous hash value and the nonce to generate the new hash
	thus, if a block is changed illegally, all the subsequent blocks change their hashes and thus have invalid hashes

everytime a new miner enters the blockchain, they get a full copy of it
so how do they decide what goes into the chain?
	if someone enters new data into their copy, they can remine the chain to make theeir chain seem valid, but it wont match up with the other copies
	this mismatch is how the system knows they have a bad chain
	so the more people have copies of the chain, the more proof of tampering we have

now, not only can we store the details of accounts like debts and assets in blocks, we can store code there
	for example, if the goal amount of money is reached, then send the money to the recipient

So this is where the Internet Computer comes in.
Back in even 2014, where most of us were not really aware of the blockchain or how it works, or even had the smarts to buy a bitcoin, the team at Dfinity started building the Internet Computer 
the idea is to build a scalable cloud computer that runs on a blockchain.
So it has all of the benefits of a trustless decentralized system, but also it allows you to perform fast computations, store data directly on the blockchain, and to be able to create fully-fledged applications on chain.

the goal of the internet computer is to reach blockchain singularity
The idea is to have a powerful, secure blockchain that's capable of running the entire base layer of the web.

the reason we still rely on other systems and processes is because it's extremely difficult with the current blockchains like Ethereum to be able to host large amounts of data and carry out a large amount of transactions
it wasn't built for that purpose.
Ethereum was built primarily to act as a ledger. 
It's not designed to handle a lot of computation or data storage.

The rate at which transactions can be processed determines how fast a blockchain-based app can run or how big it can scale.
Each new post in a decentralized social media app is a transaction. 
That means the number of transactions per second (TPS) of the blockchain itself will limit how many posts all of your users can make, because the TPS determines how fast your app can update it's state.

to solve this issue, DFINITY came up with basically a novel consensus algorithm, what they call threshold relay
it allows the Internet Computer to be able to reach much faster speeds when compared to the other major layer one blockchains that are currently in existence.

But how does it work under the hood?
Well, basically, the Internet Computer aggregates the compute capacity of a large number of independent data centers
then it takes all of these data centers around the world and combines them using the Internet Computer protocol into a large, single, decentralized world computer(this is a nickname).
And this decentralized computer is organized into individual, canisters or canister smart chains.
these canisters can basically run processes, execute code and store the data for the programs.
So as a user, you can tap into the canisters directly by making HTTPS requests.
But as a developer, what you need to realize is that this Internet Computer is basically just a whole bunch of canisters where each canister can hold programs and programs state through a web assembly module and a flat memory model called a memory page.
So you as a developer can write code that compiles into a performant way to run web applications on user hardware using web assembly and you can do that using many languages such as Rust or Dfinity's Motoko.

each of these canisters acts a bit like a process or a code sandbox.
It's kind of similar to containers if you're familiar with Docker and that kind of stuff
essentially, the program state gets preserved, so your canister kind of acts as if it runs forever.
	So imagine if you run something in CodeSandbox and you click Run and that program never gets killed,
	then all of your data can just simply be kept in their variables.

balances.get(who) returns a ?Nat not a Nat
what is ?Nat
Well, it's a data type called an Option.
Essentially, it's a typesafe null.
What it means is that it retains the data type of a particular value, but it can be null or it can have a value.

The way that we're supposed to deal with these optionals is we're supposed to use a switch statement to check if it's null or if it, in fact, is an Optional of a particular data type.

    public query func balanceOf(who: Principal ): async Nat {

		let balance : Nat = switch (balances.get(who)) {                                                                                   //dealing with the ?Nan
			case null 0;
			case(?result) result;
		};

	}

	return balance;

we want the data to persist so, make the hashmap stable

this can not work as the hashmap is a nonstable datatype

a common pattern in Motoko is to do this through a temporary variable. And that temporary variable will have a stable type
and then before the code gets upgraded, we transfer the data into the temporary variable and then after
the upgrade gets happened, we transfer the data back.

Now, why do we want to go through that process?
Well, it's because in this case, the stable type that we'll need to use is an array.

we use this method because this is a serialized data type and it's really expensive in terms of time and in terms of the Internet Computer, that will be money and computation as well, to try and get hold of items in it. 
Because it's ordered in an array, it's much easier if you knew which item of the array you wanted. 
But if you actually wanted to search through it and find each principal and then check it against the one that we want, which is what we're doing this would be really, really inefficient using an array data type.
That's why we're only going to change it into an array in between the update and then change it back once we're done.

to do this,

what is the internet identity
Up to this point, we've been claiming our DANG tokens into the current logged-in user of the frontend, which uses the Principal ID,
now the problem with this is this is actually just an anonymous user. It's actually not a real user at all.
And the reason is because we're not logged in.
So this user that's operating the website has no Principal ID to give our backend to use.

when you create an Internet Identity, you able to assign a device to that Internet Identity anchor and it would ask you to verify your identity using either a USB security key or this current laptop device

Now what exactly is this internet Identity and how can we implement it in our website to allow authentication of our users through the Internet Identity?
the idea with the Internet Identity is it's an anonymous blockchain authentication framework that is supported by the Internet Computer.

this is going to function like oauth using a third party like google or facebook

internet Identity allows us to be anonymous. 
Using the Internet Identity, we can create as many of these anchors as we want.
And these anchors give us a pseudo-identity which we can be used to log in to decentralized apps.
But you can create as many of these anchors as you want or need, and the Internet Identity at this stage knows absolutely nothing about you.

There's no username, there's no password, you don't need to provide an email to sign up, there's no seed phrases, One-Time passwords, authenticator apps, or email confirmations, which means that companies won't be able to track you across services or even know who you are.
The Internet Identity builds on this thing called the Web Authentication API, which is a specification written by W3C and FIDO with the participation of big companies like Google, Mozilla, Microsoft and others.
This means that the technology that is behind it will be compatible with all modern browsers and operating systems.
When you create an Internet Identity, it's secured using chain-key cryptography, the same framework that powers the Internet Computer. 
And it uses compatible cryptographically enabled devices such as the fingerprint sensor on a laptop or the face id system on a phone to authenticate you, which from a user's point of view makes the sign up and login super easy because you don't have to remember any passwords or usernames.
All you have to do is just sign in using your biometric data like your face or your fingerprint, which makes it super convenient
and it also eliminates the weakest point of online security, which, to be honest, is you.
It's the ability for you to generate secure enough usernames and passwords and to remember them.

So how does that actually work?
Well, when you add a device to an anchor and you generate a new Internet Identity, a pair of cryptographic keys, a private and public key, are generated.
The public key is stored on the Internet Computer blockchain, while your private key remains locked inside the authentication device, so together with any sort of biometric data that secures the access to it, for example, touch ID. 
When you log on to a decentralized app, both keys are required to authorize the session and the authorization from the Internet Identity then grants you access as an application specific anonymous identity, which basically allows you to be pseudonymous across many applications,
and it also lets you create as many of these pseudo-identities as you need.
And if you want to learn more, you can take a look at this demo from the Dfinity team, where the founder of Dfinity talks about how it works in more detail.
